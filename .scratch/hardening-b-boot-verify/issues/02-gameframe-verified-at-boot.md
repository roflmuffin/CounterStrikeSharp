# 02: GameFrame verified at boot (tracer)

Spec: `.scratch/hardening-b-boot-verify/spec.md`. ADR-0003, ADR-0004.

**What to build:** The first Slot Binding end to end: `cssharp.server/game-frame` (ISource2Server GameFrame). GameFrame's slot index and fingerprint window live in Gamedata in the additive Slot Binding shape. At boot the resolver, now behind its resolver interface, runs a Vtable Check: it finds the class vtable by RTTI, fingerprints the window and resolves the Binding when it matches, or fails it (disabling game-frame) when it does not. GameFrame is hooked by the verified slot index instead of its compiled header position. The fingerprint core is shared with a first slice of the generator: a bootstrap mode that emits the Slot Binding entry (index, window, recorded vtable size) for a named class and slot on a given build. No Heal yet.

**Blocked by:** 01; spec A 03 (C++ test target); spec A 04 (resolver and Resolution Report)

**Status:** resolved

**Tier:** 1 base · must

- [x] An x86-64 decoder is available natively (reused from an already linked hooking library if present, otherwise a small permissive one)
- [x] The C++ fingerprint matches the Python research oracle for every slot of CSource2Server on archived builds (local, skipped when the archive is absent) and on synthetic fixtures (CI)
- [x] Generator bootstrap mode emits GameFrame's Slot Binding for build 1.41.9.7 from the archive, and that entry is committed to Gamedata
- [x] Resolver unit tests (synthetic vtables): matching window resolves; mismatching window fails with reason "fingerprint mismatch"; size change alone resolves with a warning
- [x] All Binding resolution goes through the resolver interface; the built-in adapter is the only code locating Bindings
- [x] End-to-end: valid Gamedata → GameFrame hooked by index, ticks and timers work; corrupted GameFrame fingerprint → game-frame disabled, server stays up, startup report lists it
- [x] Existing readers of Gamedata by key are unaffected by the new fields
- [x] Windows builds and behaves as today (header index, reported unverified)

- **Patterns for 03–10 (follow these):**
  - **Slot Binding Gamedata shape**, documented at `SlotGamedata` in `src/core/binding_resolver.h`: the slot index stays `offsets.<os>`, plus `"vtable": { "class", "library", "linux": { "window": [fp-1|null, fp, fp+1|null], "uniqueNearby", "size" } }`. `library` uses Gamedata library names (`server`, `engine` for libengine2, `tier0`). Interface keys are `Interface::Method` (e.g. `ISource2Server::GameFrame`). A Gamedata key with `vtable` is auto-declared `BindingKind::Slot` by `CoreBindingDeclarations`, which is the hook for ticket 09. Catalog rows use `Slot("Key")` in `src/core/engine_features.cpp`.
  - **Resolver seam:** `IBindingResolver` / `BuiltinResolver(Platform)` in `src/core/binding_resolver.h`. `core_bindings.cpp` `Resolver()` is the single place an adapter is chosen. `ResolveBindings(...)` is kept as shorthand for the Linux built-in (existing tests). Slot logic is `ResolveSlot` in `binding_resolver.cpp`. Live vtables are fingerprinted once per (library, class) per Resolve. The report adds `BindingStatus::Unverified`, `FailureReason::FingerprintMismatch` (append-only; managed mirrors both by name), and `BindingResult::slot` (`SlotEvidence`: class, statedIndex, match Window/OwnFingerprint/None, live and recorded vtable size). JSON adds `status` and `slot`. Ticket 03 adds Healed and AmbiguousHeal next to these.
  - **Fingerprint core:** `src/core/vtable_fingerprint.{h,cpp}` (FP24 via Zydis, `FingerprintVtable`, `WindowAt`, `WindowMatchesAt`, `UniqueNearby`, `RecordSlot`, `CheckSlot` → `SlotMatch`). Ticket 03 extends `CheckSlot` with the heal search (after the own-fingerprint rule, before mismatch). Ticket 04 reuses `WindowMatchesAt` for carry-forward. The generator and the resolver both call it.
  - **Reading vtable slots:** never from live memory. Live run 1 failed because Metamod's loader raw-patches `ISource2Server::Init` (slot 3) during plugin load (not via KHook, so `KHook::FindOriginalVirtual` does not see it), and the live vtable "ended" at 3 slots. Slots are now the words the dynamic loader relocated: `src/core/elf_relocations.{h,cpp}` (`elf::RelocatedWords`), from `CModule::Relocations()` at boot (lazy, built from the live dynamic section) and the same reader in the archive loader. This also matches the oracle's size rule: relocated pointer into code, or pure/deleted.
  - **Hook by verified index:** `HookSlot(m_hooks, key, &Iface::Method, instance, ctx, pre, post)` in `src/core/slot_hooks.h`, gated by `bindings::ShouldRegisterHooks(features::X, "...")` (see `mm_plugin.cpp` GameFrame). It uses `HookSet::AddIndex` (new, per-instance, by runtime index). On Windows it takes the Gamedata index if one exists, else the compiled header index.
  - **Generator:** `tooling/gamedata-generator/` (`main.cpp` CLI, `generator.{h,cpp}` = `BootstrapSlotBinding(fingerprints, request, entry)`, returning entry + warnings, and `SlotRecordJson`; `build_archive.{h,cpp}` = `LoadedModule` for `.so`/`.img` and `FindArchivedModule`). It is built by `tests/native/CMakeLists.txt` as target `gamedata-generator` (Linux only). Usage: `gamedata-generator bootstrap --build 1.42.0.1 --key ISource2Server::GameFrame --class CSource2Server --library server --index 20 --gamedata configs/.../gamedata.json --out <file>`. Output uses `ordered_json` dump(2), so the diff against the committed file is only the new key. Exit 1 usage, 2 archive/build missing, 3 class/slot unusable. Ticket 04 adds a `carry-forward` command beside `bootstrap`.
  - **Tests:** synthetic resolver tests in `tests/native/slot_binding_test.cpp` (`FakeBuild` with distinct bodies via `Body(id)`; Gamedata from `vtable::RecordSlot`, as the generator records it). Generator tests are in `generator_test.cpp`. Real-build tests in `archive_test.cpp` skip per build via `FindArchivedModule(DefaultArchiveRoot(), build, "server")` (`CSSHARP_BUILD_ARCHIVE` overrides `~/dev/cs2-builds`). `real_binary_test.cpp` now uses `LoadedModule` (its own ELF loader removed).
  - **E2E corruption:** `--gamedata-jq '."ISource2Server::GameFrame".vtable.linux.window[1] = "0000000000000000"'`. Corrupt the slot's own fingerprint: a corrupted neighbour alone still resolves via the own-fingerprint rule. With game-frame disabled use `--no-smoke` (the smoke test waits on frames). Cases now match `all [0-9]+ available`.
- **Decisions applied:** all displacements masked, plus the own-fingerprint resolve rule (`uniqueNearby` recorded by the generator). ADR-0003 is amended (new "Amendment" section) and so is the spec's Implementation Decisions. A Slot Binding without a window is reported unverified at its Gamedata index (decision 3). Committed Gamedata targets 1.42.0.1: GameFrame was bootstrapped there at index 20 (the e2e SDK `ccd5b3e` header index). The 1.41.9.7 bootstrap at 19 is produced by the generator and checked in `archive_test.cpp`: same window as 1.42.0.1 (the neighbours did not change either), size 104. The committed 1.42.0.1 entry resolved against 1.41.9.7 fails with fingerprint mismatch (heal is ticket 03).
- **Oracle finding:** the C++ fingerprint matches the oracle exactly for every CSource2Server slot on all 9 archived builds. Across all 37 fixture vtables, 14 slots differ (CCSPlayerController 212, CBasePlayerPawn 267/283/334/336, CBaseEntity 212, CCSGameRules 56, on both 1.41.9.7 and 1.42.0.1, none of them ours). The cause is the oracle: capstone sizes some `66`-prefixed SSE RIP displacements as 2 bytes and leaves the upper half unmasked. The test accepts only "we zeroed bytes the oracle kept". Zydis is correct. The oracle's replay numbers are off by these slots only.
- **Deviations / notes:**
  - Decoder: no decoder is linked into the plugin (KHook's Zydis is inside Metamod and not exported). Zydis 4.0.0 is vendored as the amalgamation in `libraries/zydis` (MIT, static lib, hidden symbols), copied from Metamod's safetyhook copy.
  - Windows: no `offsets.windows` for GameFrame (I did not guess an MSVC index). The resolver reports it Unverified with offset -1 ("header index") and `HookSlot` uses the compiled index, so behaviour is as today. Windows is not compiled or run here. Ticket 09 must decide what an Unverified Slot Binding with offset -1 means for game-class virtuals, which have no header index; the likely answer is failing MissingForThisOs.
  - Startup report additions (native and managed): vtable size-change warnings and an "N Slot Binding(s) unverified" line. Timers (`AddTimer`) and the `OnTick` listener warn once on a disabled game-frame. `AddTickTimer`, `NextFrame` and `NextWorldUpdate` are not gated yet (ticket 05 territory).
  - Other RTTI lookups outside the resolver (`customhudlayout`, nav physics, plugin `VTable<T>`) are not Bindings and were left as they are.
  - Known pre-existing issue: the server exits 139 on quit.
