## Review fixes

Branch `spec-b/review-fixes` (base `hardening/impl` 84eb878a). One line per review finding.

1. **Fixed.** The generator has no window search of its own any more. Its bootstrap warning uses `vtable::WindowMatchesNear`. Carry-forward uses the new `vtable::WindowMatchesAnywhere`, which runs the same match rule through the same core loop, over the whole vtable and including the recorded index. It is not `LocateSlot`, because the generator's carry-forward rule is stricter: a changed neighbour holds the slot instead of carrying it on its own fingerprint (existing test, spec rule). Replays stay byte-identical: carrying 1.41.9.7 forward still reproduces the committed 1.42.0.1 Gamedata, and the same build still gives no diff.
2. **Fixed.** A neighbour recorded outside the vtable now matches anything only at the stated index, so a vtable grown past an unmoved slot still verifies. A Heal, and the generator away from the recorded index, need the whole window (`WholeWindowMatchesAt`): a recorded edge-null matches only an edge at the candidate. Synthetic tests cover both directions: the last slot still last heals; the last slot moved while the vtable grew fails; the first slot never heals; the generator carries or holds to match. One summary test had relied on the first slot healing; it now uses the last slot. Archive replay is unchanged: 288 resolved, 15 healed (15 of 16 known moves), 4 failed, 0 wrong. With SetStateChanged (item 11) it is 296 / 15 / 4 / 0.
3. **Fixed.** Removed "(ticket 08)" from `ServerGameClientsEngineFeatureTests.cs` and "spec B's table" from `tests/native/isource2server_test.cpp`. No other ticket or spec references are in code from `git diff hardening/spec-a...HEAD`. `SpecCatalog` in `EngineFeatureCatalogTests.cs` comes from spec A and was left alone.
4. **Fixed.** `ThrowUnavailable` and the inline `ThrowNativeError("%s", DescribeUnavailable(...))` copies now use `RequireEngineFeature`. That covers natives_server, natives_engine (GlobalVars, ClientPrint), natives_commands (ReplicateConVar, plus a duplicate include), natives_usermessages, and two equivalent spec A copies in natives_events (game event manager) and natives_schema (state-changed). Spec A's checks on null function pointers in natives_entities and FireEventToClient test a different condition and were left as they are.

Applied it where the managed check was missing: the ConVar APIs (`ConVar<T>`, `ConVarBase`, the obsolete `ConVar`: find, read, write and create, as the natives gate) and `ExecuteClientCommandFromServer`. 13 new managed test rows check the typed exception. `IsServerPaused` and `GetEconItemSystem` have no managed wrapper, so the native check is the only one. The rule is recorded in the spec.

Removed all static caches: engine_server_calls (11), server_manager (2), natives_server (2), `IsPawn`, `SetStateChanged`, `globalVarsAvailable` in globals.cpp, and the slot members of the ICvar forwarder. Each call reads the current report, so a report swapped in later is followed. Tested: the report finds Bindings after a copy or move, and `CallSlot` follows a new report.
